# Hackathon Kickoff

과제 시작 후 첫 15분 안에 끝낸다. 코드는 아직 쓰지 않는다.

## 1. 과제 해부 (BRIEF.md 작성)
과제 문서와 제공 파일을 읽고 아래 표를 채워 `BRIEF.md` 로 저장한다.

| 항목 | 내용 |
|---|---|
| 한 줄 목표 | |
| 제출물 | 파일명·형식·위치 (코드? 보고서? 예측 csv? 데모?) |
| 평가 기준 | 지표/채점 항목과 비중 |
| 입력 데이터 | 파일, 크기, 컬럼, 기간 |
| 출력 형식 | 예시 행까지 적기 |
| 제약 | 시간, 라이브러리, 인터넷, 금지 사항 |
| 모호한 점 | 사용자에게 물어볼 것 |

- 데이터 파일은 통째로 읽지 말고 `ls -lh`, `head`, `wc -l` 로만 확인한다.
- 모호한 점이 있으면 여기서 멈추고 사용자에게 질문한다.

## 2. 과제 유형 판별 → 다음 스킬
- 표/센서/로그 데이터로 예측·분류·이상탐지 → `$data-task-playbook`
- 서비스·앱·에이전트·데모를 만드는 과제 → `$product-prototype`
- 둘 다 → data 먼저 baseline, 그 결과를 product 로 감싼다

## 3. 타임라인 (10:00–14:00 기준)
| 시간 | 할 일 | 권장 모델 |
|---|---|---|
| 10:00–10:15 | 과제 해부, PLAN.md | Sol |
| 10:15–11:00 | end-to-end baseline (제출 가능한 상태 만들기) | Terra |
| 11:00–12:45 | 개선 반복 (가장 효과 큰 것부터) | Terra, 막히면 Sol |
| 12:45–13:30 | 정리·문서화·데모 다듬기 | Terra / Luna |
| 13:30–13:50 | `$submission-check` 로 최종 점검 | Sol |
| 13:50–14:00 | 제출. 새 기능 추가 금지 | - |

**11:00 에 제출 가능한 결과물이 없으면 개선을 멈추고 baseline 완성에 집중한다.**

## 4. PLAN.md
단계별로 `- [ ] 할 일 — 완료 조건` 형식으로 적는다. 단계 하나는 30분 이내 크기로 쪼갠다.
진행하면서 체크하고, 계획이 바뀌면 PLAN.md 도 고친다.
