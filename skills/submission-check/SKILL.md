# Submission Check

모든 항목은 **실제로 실행해서** 확인한다. 확인 못 한 항목은 "미확인"이라고 보고한다.

## 1. 제출물
- [ ] BRIEF.md 의 제출물 목록과 실제 파일이 1:1 로 맞는다 (이름, 확장자, 위치)
- [ ] 예측 파일이면: 행 수, 컬럼명·순서, ID 누락/중복, NaN 없음, 값 범위·dtype 확인 (코드로 검사)
- [ ] 보고서/README 의 숫자가 `outputs/results.md` 의 실제 실행 결과와 같다

## 2. 재현성
- [ ] 새 셸에서 README 의 실행 명령을 그대로 실행해 끝까지 돈다
- [ ] 시드 고정, 하드코딩된 개인 경로(`/Users/...`) 없음
- [ ] `requirements.txt` 에 실제로 쓴 패키지가 다 있다

## 3. 문서 (README.md)
- [ ] 문제 요약 / 접근 방법 / 결과(지표) / 실행 방법 / 한계
- [ ] References: 사용한 공개 저장소·스킬·라이브러리 출처 링크

## 4. 규칙
- [ ] API 키, 토큰, 개인정보가 코드·노트북 출력·로그에 없다 (`grep -rniE "api[_-]?key|token|secret|password"`)
- [ ] 활용한 외부 저장소가 모두 공개 상태다
- [ ] 결과물 전체를 외부 자료로 대체한 부분이 없다

## 5. 정리
- [ ] 디버그 print, 안 쓰는 파일, 큰 중간 산출물 정리 (제출 용량 확인)
- [ ] git 을 쓰면 마지막 상태 커밋

마지막 10분에는 새 기능을 넣지 않는다. 깨진 게 있으면 직전에 동작하던 버전으로 되돌린다.
